# Повторная проверка Deepspace — 20 ноября 2026

Проверялся только семестровый проект Deepspace. Практики 4 и 5 не входили в этот аудит.

## Что подтверждено

| Этап | Результат |
|---|---|
| Исходник | SHA256 BASIC совпал с записанным эталоном; оригинал не изменён |
| Генерация C | Повторная трансляция дала тот же файл побайтово |
| Нативная сборка | Чистая принудительная сборка make на macOS, без предупреждений |
| Основные диалоги | 23/23 для C и 23/23 для Wasm; оригинальный Vintage BASIC запущен повторно |
| Дополнительные сценарии | 36/36 для C и Wasm против Vintage BASIC, все сочетания трёх систем и трёх кораблей |
| Базовые окончания | Победа, поражение, самоуничтожение и повторный бой прошли через новый shell-скрипт |
| Веб-обработчики | Загрузка, неверный числовой ввод, раздельный ввод пары, победа, создание скачиваемого текста, перезапуск, арифметическая ошибка и восстановление после неё прошли |
| Сборки других платформ | Повторно собраны Wasm, Windows x64, Linux x64 и Linux x86 |
| История Git | Реальные коммиты присутствуют; remote не настроен, публикация не подтверждена |

Дополнительные сценарии воспроизводимы командой:

```sh
python3 tests/test_matrix.py --reference /путь/к/vintbas
```

В этой матрице 9 сценариев используют неизменённый BASIC с RND(0)=0; 27 — временную копию с контролируемыми значениями 0.25, 0.5, 0.75. Вместе с основными тестами проверено 59 сценариев каждой реализации, из них 29 на неизменённом оригинале и 30 с явно подставленным RND. Допуск сравнения прежний: относительный 2e-6, абсолютный 1e-7; пробелы нормализуются. Это не доказательство полного побайтового совпадения при любом вводе.

Тест страницы выполняет настоящие app.mjs и Wasm, но DOM имитируется. Он не проверяет визуальную вёрстку и работу системного окна скачивания в реальном браузере. Во время аудита управление пользовательским браузером или JSLinux не выполнялось.

## Что изменено после проверки

Добавлены `build.sh` и `check-smoke.sh`. Первый собирает игру без ручного набора флагов, второй делает сборку и четыре базовые проверки без Python/make/Node. Правила игры не менялись.

По пользовательскому скриншоту текущая JSLinux — **x86_64**. Прежний архив включал 32-битный запасной исполняемый файл. Исходники подходят для обеих архитектур, но запуск готового ELF32 на x86_64 зависит от поддержки в ядре. Новый `deepspace-linux.tar.gz` содержит оба варианта. Надёжный основной путь — локальная сборка через `sh check-smoke.sh`.

Ошибка на скриншоте возникла до компиляции исходников: GCC отверг `-02` и `-0`, где вместо букв O/o набраны нули. Сам по себе этот скриншот не подтверждает ни ошибку игрового кода, ни успешный запуск Linux-версии.

## Что ещё нужно для подтверждения готовности к сдаче

1. В JSLinux распаковать новый архив и получить четыре PASS от `sh check-smoke.sh`, затем запустить игру и пройти бой.
2. На Mac открыть веб-версию через сервер, пройти бой, проверить перезапуск и сохранение диалога. Сделать настоящий скриншот по `docs/SCREENSHOTS.md`.
3. Опубликовать репозиторий с историей по `docs/PUBLISH.md`. В этой рабочей копии удалённый репозиторий не задан.
4. Убедиться, что выбор Deepspace согласован с преподавателем; подтверждения согласования в переписке нет.

Windows-файл собран, но не запускался на Windows. Не следует заявлять такую проверку на защите. Требования исходного задания: https://github.com/true-grue/kisport/blob/main/pract/project.md
