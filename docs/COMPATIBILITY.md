# Совместимость с оригиналом

## Что считается эталоном

Исходник взят без изменений из [коллекции Søren Roug](https://www.roug.org/retrocomputing/languages/basic/morebasicgames/deepspace.bas). Эталонная среда — **Vintage BASIC 1.0.3** ([сайт](http://www.vintage-basic.net/download.html)). При подготовке использован официальный macOS x64 архив, запущенный на macOS ARM64 с поддержкой Intel-программ. Интерпретатор в поставку не включён.

SHA256 исходника: `1b1836ae0d9f041cae45eafdc242f73a8f2b822cc0b6ea1c7de35f2bcb730986`. Хеши интерпретатора и каждого эталонного лога находятся в `tests/reference.json`. Логи в `tests/expected` получены запуском BASIC, а не выводом C-программы.

## Особенности, которые намеренно сохранены

- В Vintage BASIC `RND(0)` возвращает предыдущее случайное значение; до первого получения случайного числа оно равно **0**. В игре используются только `RND(0)`, поэтому стандартный запуск детерминирован: начальная дистанция 500, относительная скорость 0. Это поведение выбранного диалекта, а не универсальное правило всех BASIC.
- Числа представлены `float` (32 бита), как в эталонной среде. Сборка отключает объединение операций в FMA (`-ffp-contract=off`).
- `ON ... GOTO` отбрасывает дробную часть селектора; например, 1.9 выбирает первый переход.
- Описание фазера обещает 100 выстрелов, но исходная загрузка увеличивает `N1` на количество единиц. После исчерпания фазера исходный переход продолжает расчёт урона с прежним `Z`. Это не исправлено.
- Для пустого запаса lances оригинальный переход также ведёт к расчёту урона вместо предупреждения.
- При загрузке защитного поля исходник принудительно устанавливает `C1=.20`, `N=100`, занимая 20 единиц трюма независимо от введённого количества.
- `N5` (поле) не обнуляется при повторном бое. Сохранены и остальные места, где исходник переиспользует состояние.
- Формула с отрицательной скоростью может возводить отрицательное число в дробную степень и приводить к ошибке. Модуль скорости не подставлен: это изменило бы оригинальный алгоритм.

У C-программы есть параметр `--rnd 0.5` для контролируемых проверок. Он задаёт повторяемое значение, а не начальное зерно генератора. В браузерном интерфейсе используется стандартный ноль.

## Как проверяется перенос

23 сценария охватывают инструкции, выбор систем/кораблей, загрузку трюма, оружие и исчерпание запасов, скорость, повторный бой, самоуничтожение, выход, уничтожение противника и собственного корабля. В 20 сценариях запускается неизменённый оригинал. В трёх (`fixed_half`, `fixed_quarter`, `fixed_high`) **только во временной копии** `RND(0)` заменяется на 0.5, 0.25 или 0.75. Это позволяет проверить ненулевые ветки формул; эти три проверки не выдаются за обычный запуск неизменённого исходника.

Сравниваются текст, пунктуация, порядок и значения всех чисел. Пробельное оформление нормализуется. Допуск чисел: относительный `2e-6`, абсолютный `1e-7`, из-за десятичной печати float32 и различий библиотек математических функций. Это **не побайтовое совпадение** терминальных файлов. Оригинальные и полученные логи можно просмотреть вручную; полученные логи пишутся в `build/test-logs`.

```sh
make test
make test-web
make reference-test VINTBAS=/полный/путь/к/vintbas
```

`tools/record_reference.py` предназначен для осознанной перезаписи эталонов; обычные тесты их не меняют. `tools/create_cases.py` восстанавливает входные сценарии. `make regenerate` заново переводит оригинал в `src/game.c`. Это небольшой переводчик синтаксиса конкретной игры, а не универсальный BASIC-компилятор.

## Границы проверки

Диалоговые тесты не доказывают эквивалентность на всех возможных вводах. Ошибочные вводы, очень большие числа, формат сообщений об ошибках и переполнение строк не обязаны воспроизводить интерпретатор побайтово. C-оболочка ограничивает строки и проверяет числовой ввод. На ошибке арифметики выводится диагностическое сообщение с номером строки BASIC; текст ошибки отличается от Vintage BASIC. Обе оболочки принимают пару чисел через запятую, а также последовательным вводом двух чисел.
