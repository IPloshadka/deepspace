## Что именно проверяет продвинутый тест

`tests/test_core.c` содержит небольшой воспроизводимый генератор последовательностей ввода. 2000 seed дают 2000 основных сессий; для каждого seed между двумя повторениями запускается другая сессия, чтобы загрязнить предыдущее состояние. Затем сравнивается хеш всей последовательности вывода и конечного состояния. Полный reset должен устранять влияние предыдущей сессии.

Генератор пробует разные системы/корабли, корректные и некорректные количества оружия, команды за пределами меню, изменения скорости, повторные бои и подтверждение самоуничтожения. Бюджет ограничивает сессию 200 вводами. Ожидаемые арифметические ошибки оригинала допускаются только как контролируемая ошибка, а не падение процесса. Это сочетание фаззинга и проверки свойств; 36 фиксированных дополнительных диалогов сами по себе не выдаются за продвинутый метод.

Модульная часть отдельно проверяет 9 сочетаний корабля/системы по независимой модели расхода торпед и формулу первого ракетного попадания при RND=0: урон 8. Эти проверки не читают ожидаемые значения из реализации C.

## Как проверять ОС и разрядность

Workflow `.github/workflows/verify.yml` запускает четыре задания: Linux 32, Linux 64, Windows 64, Web. Сборка без запуска не считается подтверждением работоспособности. Просмотрите успешные задания Actions, журналы и артефакты. В Linux вывод `file` подтверждает ELF32/ELF64. В Windows выполняются тесты нативного EXE через MSVC/CMake. Web запускает реальный Chromium, отдельно мышь и эмулированный touch.

До успешного завершения Actions эти проверки остаются настроенными, но не подтверждёнными. Ретро-стиль не следует выдавать за реальную ретро-платформу. Наличие исходников для Android, DOS или bare-metal не заявляется.
